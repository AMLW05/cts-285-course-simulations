MODULE 4 · BUILD BRIDGE

Design and Build a Text-Only Prototype

Use the design decision you developed in the Module 4 investigation to build a minimal text-only prototype. The goal is not visual polish. The goal is to test whether your design can survive implementation with responsibilities separated clearly enough to carry forward into later Flask work.

Required structure

Your prototype must contain three distinguishable layers:

  1. Text interface layer — receives input and displays output.
  2. Business logic layer — contains reusable rules and decisions that should not depend on one interface.
  3. Stubbed data layer — provides or preserves the minimum data/state needed to exercise the selected product slice without requiring the final database implementation.

Build from evidence: Your prototype should implement the behavior/data responsibility you justified in docs/decisions/m4-design-investigation-record.md. If implementation exposes a new contradiction, record it rather than hiding it.

Minimum prototype evidence

  • One complete product-slice path can be run from the text interface.
  • Business rules are callable outside the interface layer.
  • The data layer is replaceable/stubbed rather than hard-coded throughout the interface.
  • State required by the selected behavior is represented deliberately.
  • At least one acceptance criterion from the selected product slice can be demonstrated through the prototype.
  • The README or code comments identify what is intentionally stubbed and what remains unresolved.

Submit in Canvas

Submit the direct GitHub link to the prototype location in your CTS-285 repository. Your submission should make it possible for the instructor to locate:

  • the text interface entry point;
  • the business logic;
  • the stubbed data layer;
  • the related m4-design-investigation-record.md.

Do not upload duplicate code files to Canvas. GitHub is the source of truth for the prototype.
