# Module 4 — Alignment and Sequence Map

## Module Title
From Product Work to Build-Ready Design

## Governing Question
What do we still need to ask, know, see, test, or resolve before this product work is safe and clear enough to build?

## MLOs

### MLO 4.1 — Frame Design Questions and Select Evidence
Identify an implementation-relevant design question and select/create appropriate evidence to answer it rather than documenting by habit.

### MLO 4.2 — Develop and Test Implementation-Supporting Design
Create design evidence and a minimal three-layer text prototype that clarify interaction, behavior, architecture, and data decisions with traceability.

### MLO 4.3 — Evaluate and Revise Build Readiness
Evaluate product work using design evidence, prototype behavior, acceptance criteria, dependencies, Definition of Done, and unresolved uncertainty; revise, split, defer, block, or proceed based on evidence.

## Governing Reasoning Loop
Question → Evidence → Decision → Consequence → Evaluation → Revision → Next Question

## Learner Sequence

### 1. Canvas — Design for Implementation
**Purpose:** Teach the distinction between product work and implementation-supporting design; introduce question-first evidence selection and the three-layer bridge.
**Primary alignment:** MLO 4.1, foundation for 4.2.
**Submission:** None.

### 2. External — Design Decisions Practice Cabinet
**Purpose:** Repeated judgment practice: useful questions, evidence selection, layer responsibility, model consequences, build readiness.
**Primary alignment:** MLO 4.1–4.3 formative practice.
**Submission:** None.

### 3. External — DataMan Design Investigation Brief
**Purpose:** Student selects a Module 3 product slice, frames an implementation uncertainty, and chooses initial evidence.
**Primary alignment:** MLO 4.1.
**Record:** `docs/design/m4-investigation-brief.md`
**Submission:** Not graded separately; retained for later comparison.

### 4. External — Answer Flow Lab
**Purpose:** Operate and revise a simulated two-attempt design; expose consequences of rule location, attempt representation, persistence, and feedback responsibility.
**Primary alignment:** MLO 4.2; prepares 4.3.
**Record:** contributes to M4 Lab Evidence Record.
**Submission:** Not graded separately.

### 5. External — Memory Bank & Curator Retrieval Lab
**Purpose:** Operate and revise a simulated data design; stress the ten-problem ceiling and later curator retrieval.
**Primary alignment:** MLO 4.2; prepares 4.3.
**Record:** contributes to M4 Lab Evidence Record.
**Submission:** Not graded separately.

### 6. Canvas — Post-Lab Evidence Check
**Purpose:** Student records evidence that materially changes the investigation and revises the guiding question if needed.
**Primary alignment:** transition from MLO 4.2 to 4.3.
**Record:** `m4-lab-evidence-record` retained in repo/workspace.
**Submission:** None.

### 7. External — DataMan Design Studio
**Purpose:** Transfer controlled lab lenses to the student's own selected product slice; choose/create only the representations needed to answer the revised question; critique, revise, and determine readiness.
**Primary alignment:** MLO 4.1–4.3 integrated.
**Record:** `docs/decisions/m4-design-investigation-record.md`

### 8. Canvas Assignment — Design Investigation Application
**Purpose:** Grade the student's evidence-based design decision, traceability, revision, tradeoff, readiness disposition, and next question.
**Primary alignment:** MLO 4.1 and MLO 4.3; design evidence component supports MLO 4.2.
**Submission:** Direct GitHub link to `docs/decisions/m4-design-investigation-record.md`.
**Points:** 12.

### 9. Canvas New Quiz — Build Readiness Check
**Purpose:** Verify transfer to unfamiliar design situations without relying on the student's own project narrative.
**Primary alignment:** MLO 4.1–4.3.
**Format:** stimulus + categorization + matching + ordering + limited multiple choice.
**Recommended points:** 8.

### 10. Canvas Assignment / GitHub — Design and Build Text-Only Prototype
**Purpose:** Test whether the design decision survives implementation in three layers.
**Primary alignment:** direct assessment of MLO 4.2; evidence can also expose new MLO 4.3 revision needs.
**Submission:** Direct GitHub link to prototype location plus trace to `m4-design-investigation-record.md`.

## Artifact Chain

1. `docs/design/m4-investigation-brief.md`
   - starting question + planned evidence
2. M4 Lab Evidence Record
   - controlled simulation evidence + revisions
3. `docs/decisions/m4-design-investigation-record.md`
   - student-selected investigation + build-readiness decision
4. Three-layer text prototype
   - implementation test of the design decision

The artifacts are intentionally cumulative. Students should not recreate the same reflection at every step.

| 4.1 Frame questions/select evidence | Canvas instruction | Cabinet + Investigation Brief | Design Studio | Design Investigation Application + Build Readiness Check |
| 4.2 Develop/test implementation-supporting design | Canvas instruction + representation guidance | Cabinet | Answer Flow Lab + Memory Bank Lab + Studio | Design evidence criterion + Three-layer prototype + Build Readiness Check |
| 4.3 Evaluate/revise readiness | readiness/disposition instruction | Cabinet + lab consequences | Studio critique/revision | Design Investigation Application + Build Readiness Check; prototype may trigger revision |

## Scope Control
- No artifact is required merely because it is a common design artifact.
- The Practice Cabinet is practice only.
- Controlled labs teach through consequences; they are not duplicate graded submissions.
- The Design Studio should transfer lab learning to the student's own product slice rather than reteach the controlled examples as new content.
- Canvas captures application and assessment; GitHub/Codespaces carries forward the design and prototype work.
