Station 5: The menu becomes a page

Build the menu from links. Use url_for so a path can change in one place.

What you change

You replace the text menu with a home page. The home route / shows home.html. That page has three links: Practice, Report and Memory Bank. Each link is built with url_for, which takes the name of a Python function and returns its path. You also add a Back to menu link to the other three templates.

Before and after

This is the menu loop in menu.py. The dictionary maps a typed word to a function. The loop asks again and again.

menu.py · before · excerpt

    actions = {"practice": practice, "report": report, "bank": bank}
    while True:
        choice = input("practice / report / bank / quit > ").strip().lower()
        if choice == "quit":
            break
        if choice in actions:
            actions[choice](store)

In app.py you already wrote the dictionary's job. Each @app.route(...) line says this path runs this function. Flask keeps that map. Flask also owns the loop: it waits, and each request runs one function. Nothing is left for a while True or an actions dictionary to do in app.py. menu.py still has them, and it still runs.

Only home() changes in app.py. Before:

app.py · station 4 · excerpt

@app.route("/")
def home():
    return "DataMan is running on the web."

After:

app.py · station 5 · excerpt 

@app.route("/")
def home():
    return render_template("home.html")

Why url_for

url_for("practice") takes the name of the function, not the path. Flask looks up the path for that function and returns it. If you change the path in one place, every link follows. A path typed by hand in a template does not follow.

Steps

  1. Change home() in app.py as shown above.
  2. Create templates/home.html.
  3. Add the Back to menu line to practice.html, report.html and bank.html. The complete files are below.

Trap: a path where a function name belongs

You write url_for('/practice') with the path inside. url_for wants the function name, 'practice'. The symptom is an error page when you open any page that has the link. The error says werkzeug.routing.exceptions.BuildError: Could not build url for endpoint '/practice'. Did you mean 'practice' instead? Remove the slash.

Predict first: you change @app.route("/practice") to @app.route("/drill"). Which links break?

None of them. url_for("practice") uses the function name, and the function is still called practice. The home page link now points to /drill. The practice form has no action, so it posts to the page it is on, and it also follows. A link you typed by hand as /practice, or a bookmark, would break and give a 404 page. That is why the templates use url_for.
