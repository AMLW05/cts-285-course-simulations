AlgoCratic Futures™ asks you to web-enable DataMan without disrupting core value logic. In plain words: you replace the text menu with a web app. The rules of DataMan do not change.

What changes and what does not

One file changes: app.py. You also add a templates/ folder with HTML files.

Three files do not change. The tests prove the library stayed the same. They do not run your web pages, so each station also has a browser check. Use each page and compare it with what the old menu did.

  • dataman/logic.py — the business rules.
  • dataman/store.py — the data layer.
  • tests/test_logic.py — the tests. They pass after every station.

You rename the old app.py to menu.py and keep it. The text menu then keeps working beside the web app. Both use the same library and the same store file. You never have half a menu and half a web app.

GET and POST

  • GET asks for a page. It must not change anything. You can open it twice safely.
  • POST sends data that changes something. In DataMan it saves an attempt or adds a problem.
  • One route can handle both: methods=["GET", "POST"] and if request.method == "POST":.
  • The form's name="answer" is the key in request.form. The string is the same in both files.
