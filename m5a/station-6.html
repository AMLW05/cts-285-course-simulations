What you change

You find a defect first, then fix it. When you refresh the page after a wrong answer, the browser sends the answer again and spends the learner's second try. You fix this with Post/Redirect/Get. After a POST, the route does not draw a page. It sends the browser to a GET of the same page. The message travels to that next request with flash().

The translation row

Text menu (menu.py)Flask (app.py)
Local variables that live while the loop runsNothing survives between requests except what the store keeps. A message to show on the next page needs a way to travel. flash() is that way.

Part 1: see the defect

Do this with your station 5 code. Do not change any code yet.

  1. Stop the server with Ctrl+C. Delete the file dataman_store.json. This gives you a clean session with no attempts. (The file is not committed, and the delete also empties the Memory Bank set. You can add problems again later.) Start the server again.
  2. Open /practice. The page shows Try 1. Type 5 and press Check.
  3. The page shows Not yet. Try again. and Try 2. You answered once.
  4. Press the refresh button of the browser. The browser asks whether to send the form again. Accept.
  5. The page shows The answer is 56. The session is finished. Open /report. It lists two attempts. You typed one answer.

The rule in logic.py did its work: two tries. The page spent a try that the learner did not choose. A refresh repeats the last request, and the last request was a POST. A GET is safe to repeat. A POST is not.

Part 2: the fix

Four things change in app.py.

  • The import line brings in flash, redirect and url_for.
  • app.secret_key is set. flash() keeps the message in a signed cookie. Flask cannot sign the cookie without a key. The value in the file is for development only and it is not a real secret. Never put a real secret in a repository.
  • Each msg = ... becomes flash(...). The two routes end their POST branch with return redirect(url_for("...")).
  • The templates read the messages with get_flashed_messages(). You do not pass message to render_template any more.

The browser's last request is now a GET of /practice. A refresh repeats the GET. A message is removed when get_flashed_messages() returns it, so a refresh shows no message.

app.py · station 6 · complete file 

"""Station 6: The refresh problem. This file replaces the text menu in menu.py.

It is the only file that knows about Flask, requests, or HTML.
dataman/logic.py and dataman/store.py did not change.

Run:  python -m flask --app app run --debug --host=0.0.0.0
"""
from flask import Flask, flash, redirect, render_template, request, url_for

from dataman.logic import (MemoryBank, PracticeSession, Problem, SetFull,
                           curator_report)
from dataman.store import JsonFileStore

app = Flask(__name__)
app.secret_key = "dev-only-change-me"   # signs flash messages; not a real secret

STORE = JsonFileStore()     # one store for the whole program, made once
PROBLEM = Problem("P1", "7 x 8", 56)
SESSION = "maya-1"


@app.route("/")
def home():
    return render_template("home.html")


@app.route("/practice", methods=["GET", "POST"])
def practice():
    session = PracticeSession(STORE, SESSION, PROBLEM)
    if request.method == "POST":
        raw = request.form.get("answer", "")
        if session.is_finished():
            flash("This session is finished. Choose report.")
        elif not raw.strip().lstrip("-").isdigit():
            flash("Enter a whole number.")
        else:
            out = session.submit(int(raw))
            if out.status == "correct":
                flash("Correct.")
            elif out.status == "retry":
                flash("Not yet. Try again.")
            else:
                flash(f"The answer is {out.revealed_answer}.")
        return redirect(url_for("practice"))
    return render_template("practice.html", problem=PROBLEM,
                           try_number=session.next_try(),
                           finished=session.is_finished())


@app.route("/report")
def report():
    rep = curator_report(STORE, SESSION, PROBLEM.id)
    return render_template("report.html", session_id=SESSION, rep=rep)


@app.route("/bank", methods=["GET", "POST"])
def bank():
    memory_bank = MemoryBank(STORE, "set-1")
    if request.method == "POST":
        pid = request.form.get("problem_id", "").strip()
        try:
            memory_bank.add_problem(pid)
            flash(f"Added. Set holds {len(memory_bank.members())}.")
        except SetFull as err:
            flash(f"Refused: {err}")
        return redirect(url_for("bank"))
    return render_template("bank.html", members=memory_bank.members())

Trap: no secret key

You add flash() and forget app.secret_key. The first POST fails. The browser shows Internal Server Error. In the terminal, and on the debug page, the error is RuntimeError: The session is unavailable because no secret key was set. followed by Set the secret_key on the application to something unique and secret. The failure happens when flash() runs. The answer was already saved before that. The learner's try is spent, and the page shows an error. Add the app.secret_key line below the line that creates app.

Predict first: after the redirect, you refresh the practice page. Does the flashed message show again?

No. The template calls get_flashed_messages(). That call returns the messages and removes them. The refresh is a new GET, and no message is waiting. The page shows the form and the try number from the store.
