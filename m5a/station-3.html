Before: the loop in menu.py

This is the old function. One call runs the whole practice. The loop waits for each typed line.

menu.py (old practice function, excerpt)

def practice(store):
    session = PracticeSession(store, SESSION, PROBLEM)
    if session.is_finished():
        print("This session is finished. Choose 'report'.")
        return
    while not session.is_finished():
        raw = input(f"Try {session.next_try()}: {PROBLEM.prompt} = ")
        if not raw.strip().lstrip("-").isdigit():
            print("Enter a whole number.")
            continue
        out = session.submit(int(raw))
        if out.status == "correct":
            print("Correct.")
        elif out.status == "retry":
            print("Not yet. Try again.")
        else:
            print(f"The answer is {out.revealed_answer}.")

After: one route in app.py

app.py 

"""Station 3: Practice, GET and POST. This file replaces the text menu in menu.py.

It is the only file that knows about Flask, requests, or HTML.
dataman/logic.py and dataman/store.py did not change.

Run:  python -m flask --app app run --debug --host=0.0.0.0
"""
from flask import Flask, render_template, request

from dataman.logic import PracticeSession, Problem, curator_report
from dataman.store import JsonFileStore

app = Flask(__name__)

STORE = JsonFileStore()     # one store for the whole program, made once
PROBLEM = Problem("P1", "7 x 8", 56)
SESSION = "maya-1"


@app.route("/")
def home():
    return "DataMan is running on the web."


@app.route("/practice", methods=["GET", "POST"])
def practice():
    session = PracticeSession(STORE, SESSION, PROBLEM)
    msg = None
    if request.method == "POST":
        raw = request.form.get("answer", "")
        try:
            answer = int(raw)
        except ValueError:
            answer = None
        if session.is_finished():
            msg = "This session is finished. Choose report."
        elif answer is None:
            msg = "Enter a whole number."
        else:
            out = session.submit(answer)
            if out.status == "correct":
                msg = "Correct."
            elif out.status == "retry":
                msg = "Not yet. Try again."
            else:
                msg = f"The answer is {out.revealed_answer}."
    return render_template("practice.html", problem=PROBLEM,
                           try_number=session.next_try(),
                           finished=session.is_finished(), message=msg)


@app.route("/report")
def report():
    rep = curator_report(STORE, SESSION, PROBLEM.id)
    return render_template("report.html", session_id=SESSION, rep=rep)

How it works

  • methods=["GET", "POST"] tells Flask that this route accepts both. Without it, Flask accepts only GET.
  • request.method tells you which one this request is. The if request.method == "POST": branch runs only when someone submits the form.
  • A GET skips that branch. It shows the form and changes nothing.
  • The form has name="answer". request.form.get("answer", "") reads the same string. The name in the template and the key in the route must match exactly.
  • <form method="post"> has no action. The browser posts to the same URL it came from.
  • The while loop is gone. Each submit is one request. A request answers one try. The route asks the store which try is next: session.next_try(). The store keeps the attempts. The route keeps nothing.
Channel Success Partner · SHODANNBefore, you waited on a loop. Now the browser waits for you. I count this as a growth in patience. For the browser.

What stays in the interface and what stays in the library

Turning the typed text into a number stays in app.py. It is about reading text from a form. The library takes an integer. int(raw) does the work. If the text is not a whole number, int() raises ValueError, and the route shows a message instead of an error page. This is safer than testing the text with isdigit() first: isdigit() accepts text such as ² that int() then refuses.

The two-try rule stays in dataman/logic.py. session.submit() decides whether to retry or reveal the answer. The route only shows the result.

Why STORE is a JsonFileStore

The debug reloader restarts the program every time you save a file. A MemoryStore made at the top of app.py would be empty after each save. JsonFileStore writes to a file, so your attempts survive the restart.
